The question

A process owner doesn't ask 'does the agent work?'

They ask three things the twin answers with evidence:

Does it work together?

Nine agents that each pass their own tests can still fail as a process: a hand-off loses a field, or a gateway routes on nothing.

Is it actually better?

'86% automatable' is a forecast. Cycle time, people's time and cost per case, against today, are evidence.

Where does it break?

Which kind of invoice goes wrong, which step still needs people, and what to fix before go-live.

The fixes

What changed between run 1 and run 3

  • Sandbox: 'Document Generation Service' is now backed by Supplier email (was Invoice inbox).
  • Sandbox: 'NLP Entity Recognition Model' is now backed by Invoice inbox (was an LLM).
  • Runtime: an agent whose final answer isn't valid JSON gets one recorded repair turn, as a production runtime would do.

Before production

What the twin proves, and what it doesn't yet

Proven in the twin

  • The whole process works together, on realistic data
  • Which invoices go wrong, and why, per step and per kind
  • The business case, on stated assumptions, with ranges
  • Fixes measured on the same cases before they ship

Still needed for production

  • A production agent runtime with identity and a kill switch
  • Real connectors to ERP, vendor master and bank
  • Queueing under load (waits are sampled, not simulated)
  • Enterprise identity, tenancy and data protection (see the enterprise-readiness deck)
